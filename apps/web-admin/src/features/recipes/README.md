# Адміністративне керування рецептами

Розділ `/recipes` містить пошук і фільтри, create/edit form, inline створення
автора, nutrition preview та lifecycle actions. Dynamic ingredients і steps
реалізовані як впорядковані fieldsets із доступними labels, field-level errors і
live announcements.

Після першого збереження рецепта редактор відкриває завантаження JPEG, PNG або
WebP до 5 MiB. Зображення проходить серверну перевірку, відображається через
короткоживий signed thumbnail, а перше активоване зображення автоматично стає
основним. Галерея підтримує контрольоване видалення без публічного bucket.

Кухні та дієтичні позначки вибираються у searchable dropdown із checkbox без
необхідності використовувати системні комбінації клавіш. Пошук продукту для
інгредієнта виконується на сервері після введення щонайменше двох символів;
результати містять назву, категорію та бренд. Редактор не завантажує обмежений
початковий список каталогу, а під час редагування зберігає назви вже вибраних
продуктів.

Nutrition preview подає загальну вагу й відсортовану таблицю нутрієнтів із
локалізованими одиницями виміру та читабельним округленням. Позначка `Часткові`
означає, що принаймні один обов’язковий інгредієнт не має значення відповідного
нутрієнта: показана сума відомих значень, а фактична кількість може бути більшою.
Опційні інгредієнти не впливають ані на суму, ані на completeness.

Форма вводить ingredient mass у грамах. API додатково підтримує MASS units і
product portions, але складні conversion controls не дублюються у поточному UI.
Порожня дочірня колекція означає явну заміну; усі секції надсилаються разом для
атомарного збереження.
