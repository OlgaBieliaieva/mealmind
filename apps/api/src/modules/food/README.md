# Модуль пошуку їжі

Модуль `food` є application query над канонічними каталогами продуктів і рецептів. Він не дублює їхню доменну модель і не приймає `familyId` від клієнта.

## HTTP-контракти

- `GET /api/v1/food/search` — спільний пошук із типом `all | product | recipe`, family favorites, фільтрами рецептів і стабільною пагінацією;
- `GET /api/v1/food/products/:id` — клієнтські деталі активного продукту, нутрієнти, порції та пов’язані рецепти;
- `GET /api/v1/food/recipes/:id` — деталі видимого опублікованого рецепта;
- `PUT /api/v1/food/favorites/:kind/:id` — ідемпотентне додавання до сімейного обраного;
- `DELETE /api/v1/food/favorites/:kind/:id` — видалення із сімейного обраного.

Звичайний пошук продуктів потребує двох символів. Для `favorites=true` порожній запит дозволений, щоб відкрити всю сімейну книгу. Для `type=recipe` порожній запит повертає рецепти від найновіших і використовується для блоку останніх доданих рецептів. Рецепти можна фільтрувати за складністю, типом, автором, інгредієнтом, кухнею та дієтичною позначкою. Product visibility — `ACTIVE`; recipe visibility — `PUBLISHED` і `PUBLIC` або `FAMILY` поточної активної сім’ї.

Всі маршрути мають authentication, rate limiting і беруть єдину активну сім’ю з серверного контексту. Presenter не повертає lifecycle, audit чи persistence-only поля.

Raw SQL пошуку перевіряється лише проти ізольованої локальної бази `mealmind_test` командою `npm run api:test:food:db` після `npm run db:test`.

## Клієнтська поведінка

Web-client використовує 300 мс debounce, query cache, детерміновану сторінкову навігацію й optimistic favorite mutation із rollback та invalidation. Картки показують макронутрієнти, довідникові характеристики та короткочасні signed URL приватних мініатюр. Якщо медіа немає або воно тимчасово недоступне, продукти й рецепти відображають emoji-placeholder за категорією або типом без відмови всього пошуку.

Detail presenter повертає оригінальне основне зображення для hero, мініатюри
інгредієнтів і related recipes, але не повертає object paths. Поживність рецепта
на 100 г використовує збережений snapshot. Для історичних записів без snapshot
read model без запису до БД обчислює його з актуальних нутрієнтів обов’язкових
інгредієнтів. Якщо yieldWeightG відсутня, загальна вага визначається як сума
ваги всіх інгредієнтів. Макронутрієнти інгредієнта масштабуються за його
gramWeight. Навігація з detail page відновлює вкладку, пошуковий запит і
фільтри discovery page через перевірений внутрішній returnTo.

Клієнт не показує технічну ознаку completeness. Вона залишається в API для
контролю якості даних і майбутніх адміністративних перевірок. Додаткову
фотогалерею показано лише за наявності щонайменше трьох доступних зображень;
відео відображаються окремими зовнішніми картками.
