# Модуль тижневого плану харчування

Модуль `meal-plan` у PR-014 є виключно read model. Створення `MealEntry`, вибір кількості, учасника і прийому їжі належать PR-015.

`GET /api/v1/meal-plans/week?date=YYYY-MM-DD` повертає:

- канонічні межі тижня за `Family.weekStartsOn`;
- timezone сім’ї як частину календарного контракту;
- назву сім’ї для заголовка клієнтського плану;
- сім днів, об’єднання активних типів прийомів їжі з налаштувань профілів членів сім’ї та entries у порядку `date → mealType.sortOrder → position`;
- представлення учасників із фактичними порціями, агрегованими базовими нутрієнтами та актуальними нормами.

Читання порожнього тижня не створює `MealPlan`: відповідь має `planId: null` і повну порожню структуру. Типи прийомів їжі не беруться з усього довідника: read model повертає лише унікальні активні типи, вибрані хоча б в одному актуальному профілі сім’ї. Prisma repository виконує фіксований набір запитів із вкладеними relations, без запиту на кожен entry.

Для продукту нутрієнти масштабуються з `valuePer100g` за `quantityInGrams`. Для рецепта використовується частка `quantityInGrams / yieldWeightG`. Якщо вихід рецепта, нутрієнт або target відсутній, read model повертає `partial` чи `unavailable`; відсутнє значення не підмінюється нулем і не подається як медична рекомендація.

UI має погоджені режими «за прийомами» і «за людьми». Окремого day view немає: один або кілька днів вибираються у спільному day selector, а стан дати, multi-day і режиму зберігається в URL.
